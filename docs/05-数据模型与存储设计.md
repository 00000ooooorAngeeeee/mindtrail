# 05 · 数据模型与存储设计

> 版本：v0.2 ｜ 状态：已定稿 ｜ 依据：PRD 02 + 架构 04 ｜ 面向：后端开发、数据库实现 agent

## 1. 设计原则

1. **MySQL 为唯一事实源**：所有业务数据落 MySQL；前端无本地数据库
2. **导图整图存储**：一张导图 = 一行 + 一个 JSON 字段（`content_json`），不做节点级表——图结构递归查询复杂度高，整图读写简单且事务一致（单机场景无需多人并发改同一张图）
3. **记录结构化**：会话/条目严格表化，保证"给 agent 读"的确定性
4. **冗余列用于搜索**：`search_text` 由应用层维护，规避 MySQL 对 JSON 列建全文索引的限制
5. **幂等建表**：schema.sql 可重复执行

## 3. 建表脚本（schema.sql 核心，幂等）

> 完整脚本在 M0 阶段落库为 `backend/src/main/resources/db/schema.sql`；下方为权威定义。字符集统一 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`（MySQL 8 默认）。

```sql
CREATE TABLE IF NOT EXISTS workspace (
  id          BIGINT       NOT NULL AUTO_INCREMENT,
  name        VARCHAR(100) NOT NULL COMMENT '工作区名称',
  description TEXT         NULL COMMENT '描述',
  repo_path   VARCHAR(500) NULL COMMENT '关联 Git 仓库绝对路径（可选）',
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_workspace_updated (updated_at)
) ENGINE=InnoDB COMMENT='工作区（=一个项目）';

CREATE TABLE IF NOT EXISTS mindmap (
  id           BIGINT       NOT NULL AUTO_INCREMENT,
  workspace_id BIGINT       NOT NULL,
  name         VARCHAR(100) NOT NULL COMMENT '导图名称',
  content_json JSON         NOT NULL COMMENT '整图数据，结构见 §4',
  search_text  VARCHAR(8000) NOT NULL DEFAULT '' COMMENT '冗余文本：所有节点文本+标签+名称，供全文搜索',
  node_count   INT          NOT NULL DEFAULT 0 COMMENT '节点数（冗余统计）',
  created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_mindmap_workspace (workspace_id),
  FULLTEXT KEY ft_mindmap_search (search_text) WITH PARSER ngram
) ENGINE=InnoDB COMMENT='思维导图（整图 JSON 存储）';

CREATE TABLE IF NOT EXISTS session (
  id           BIGINT       NOT NULL AUTO_INCREMENT,
  workspace_id BIGINT       NOT NULL,
  title        VARCHAR(200) NOT NULL COMMENT '会话标题',
  status       ENUM('active','completed') NOT NULL DEFAULT 'active',
  repo_path    VARCHAR(500) NULL COMMENT '会话级 Git 仓库路径，覆盖工作区设置',
  start_head   CHAR(40)     NULL COMMENT '会话开始时仓库 HEAD（用于提交感知）',
  end_head     CHAR(40)     NULL COMMENT '会话结束时 HEAD',
  summary      TEXT         NULL COMMENT '结束总结（渲染为 review 条目）',
  started_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  ended_at     DATETIME     NULL,
  created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_session_workspace (workspace_id),
  KEY idx_session_status (status)
) ENGINE=InnoDB COMMENT='vibecoding 记录会话';

CREATE TABLE IF NOT EXISTS entry (
  id         BIGINT       NOT NULL AUTO_INCREMENT,
  session_id BIGINT       NOT NULL,
  seq        INT          NOT NULL COMMENT '会话内序号（时间线顺序），从 1 递增',
  type       VARCHAR(20)  NOT NULL COMMENT 'goal|context|prompt|action|artifact|decision|error|test|review|next|note',
  content_md TEXT         NOT NULL COMMENT 'Markdown 正文',
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间（可手动补记）',
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_entry_session_seq (session_id, seq),
  FULLTEXT KEY ft_entry_content (content_md) WITH PARSER ngram
) ENGINE=InnoDB COMMENT='时间线条目';

CREATE TABLE IF NOT EXISTS tag (
  id           BIGINT      NOT NULL AUTO_INCREMENT,
  workspace_id BIGINT      NOT NULL,
  name         VARCHAR(50) NOT NULL,
  created_at   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_tag_workspace_name (workspace_id, name)
) ENGINE=InnoDB COMMENT='标签（工作区级）';

CREATE TABLE IF NOT EXISTS entry_tag (
  entry_id BIGINT NOT NULL,
  tag_id   BIGINT NOT NULL,
  PRIMARY KEY (entry_id, tag_id)
) ENGINE=InnoDB COMMENT='条目-标签多对多';

CREATE TABLE IF NOT EXISTS entry_commit (
  entry_id   BIGINT       NOT NULL,
  commit_hash CHAR(40)    NOT NULL COMMENT 'Git commit 完整 hash',
  repo_path  VARCHAR(500) NOT NULL COMMENT '提交来源仓库（多仓库备用）',
  bound_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (entry_id, commit_hash),
  KEY idx_commit_repo (repo_path, commit_hash)
) ENGINE=InnoDB COMMENT='条目-Git 提交绑定';

CREATE TABLE IF NOT EXISTS setting (
  k          VARCHAR(100) NOT NULL,
  v          TEXT         NOT NULL,
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (k)
) ENGINE=InnoDB COMMENT='应用设置';
```

**外键策略**：MVP 不建物理外键（性能与迁移灵活性），由 service 层保证引用完整性；级联删除在 service 层显式处理（删除工作区 → 删导图/会话/条目/标签）。

## 4. 导图 `content_json` 结构（v1）

```json
{
  "version": 1,
  "rootNodeId": "n1",
  "nodes": {
    "n1": {
      "id": "n1",
      "text": "思迹 TrailMind",
      "note": "可选 Markdown 备注",
      "style": { "color": "indigo", "bold": true, "shape": "rounded" },
      "tags": ["愿景"],
      "parentId": null,
      "layout": null,
      "collapsed": false
    },
    "n2": {
      "id": "n2",
      "text": "思维导图",
      "note": "",
      "style": { "color": "default", "bold": false, "shape": "rounded" },
      "tags": [],
      "parentId": "n1",
      "layout": { "x": 320, "y": 120 },
      "collapsed": false
    }
  },
  "edges": [
    { "id": "e7", "source": "n5", "target": "n9", "type": "free", "label": "可补充" }
  ]
}
```

> 注意（M1 起落地约定）：树边（parent-child）**不落库**，由 `nodes[].parentId` 派生渲染；`edges[]` 仅存自由连线（type=free，M2 画布模式使用）。避免层级关系双份存储漂移。

字段语义：

| 字段 | 语义 |
|---|---|
| `version` | 结构版本，用于未来迁移 |
| `nodes` | 节点 Map（id → 节点）；id 为会话内唯一字符串 |
| `layout` | `null` = 树模式（坐标由布局算法实时计算）；`{x,y}` = 画布模式坐标 |
| `style.shape` | `rounded` 圆角矩形 / `rect` 矩形 / `ellipse` 椭圆 / `diamond` 菱形 |
| `edges[].type` | `free` 自由连线（画布模式）；树边 `parent-child` 为渲染派生概念，不存 edges[]（见上方注意） |
| `collapsed` | 树模式折叠状态（画布模式忽略） |
| 节点 `tags` | 节点标签（文本级，MVP 不入 tag 表，见 §6 决策记录） |

**保存语义**：前端编辑后 800ms 防抖 → `PUT /mindmaps/{id}` 整图覆盖写；后端更新 `search_text`（拼接 name + 全部节点 text/note/tags + 边 label）与 `node_count`。

## 5. 关键查询与索引设计

| 场景 | 实现 | 说明 |
|---|---|---|
| 时间线加载 | `WHERE session_id=? ORDER BY seq LIMIT ? OFFSET ?` | 每页 50；用 seq 而非时间保证插入序 |
| 会话内新条目 | `MAX(seq)+1` 计算 | service 层事务内完成 |
| 全局搜索-条目 | `MATCH(content_md) AGAINST(? IN NATURAL LANGUAGE MODE)` | 中文 ngram 分词 |
| 全局搜索-导图 | `MATCH(search_text) AGAINST(?)` | 命中即显示导图名+片段 |
| 标签筛选条目 | `entry_tag JOIN entry WHERE tag_id=?` | 会话内过滤加 `session_id` 条件 |
| 提交感知 | JGit 实时读取仓库 `since=start_head` 的提交 | 不落库；每 5s 轮询 |
| 工作区统计 | `SELECT COUNT(*) FROM mindmap/session WHERE workspace_id=?` | 列表页展示 |

## 6. 决策记录（ADR）

| 决策点 | 决策 | 备选 | 理由 |
|---|---|---|---|
| 导图存储 | 整图 JSON（一行一图） | 节点/边独立表 | 单机单用户、无并发编辑；图遍历复杂度转移给应用层（布局算法已需要全量数据）；写入原子 |
| 节点标签 | 存 JSON 内文本级 | 节点表化 + tag 多态关联 | 避免为"次要功能"引入多态关联表；搜索仍可命中（search_text 含 tags）；升级路径：P2 节点表化时迁移 |
| 搜索索引 | 应用层冗余列 `search_text` | MySQL 8 生成列 | 生成列提取"全部节点文本"语法复杂易错；冗余列由后端维护，可控 |
| 全文引擎 | MySQL FULLTEXT(ngram) | 自建倒排索引 | 万级数据量足够；零组件 |
| 时间线顺序 | `seq` 自增序号 | created_at 排序 | 支持"补记时间"场景下顺序稳定；未来支持插入位置 |
| commit 存储 | 只存 hash 与仓库路径 | 缓存 commit 元数据表 | 元数据实时从仓库读取即可；避免与仓库实际历史不同步 |
| 物理外键 | 不用，service 层保证 | 物理 FK | 便于未来分表/迁移；级联删除显式可控 |

## 7. 数据规模预估（性能预算依据）

- 单人使用：工作区 < 50，导图 < 500，会话 < 1000，条目 < 2 万
- 上限设计目标：条目 10 万、单图节点 2000，仍满足 NFR（见 04 文档 §8）
- 超出警戒线时的演进：搜索换 Lucene（单列升级）、导图节点表化——均记录于 09 风险文档

## 8. 备份与恢复

- 导出维度（产品功能）：会话 → Markdown/JSON；导图 → PNG/OPML（P1）
- 全量备份：`POST /backup/export` 输出 JSON 压缩包（P1）；导入恢复（P2）
- 运维建议：MVP 阶段用户自行 `mysqldump` 即可（文档提示，不实现 UI）
