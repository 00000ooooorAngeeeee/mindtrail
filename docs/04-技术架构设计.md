> 版本：v0.2 ｜ 状态：已定稿 ｜ 依据：PRD 02 + 数据模型 05 ｜ 面向：全栈开发、架构实现 agent

## 1. 架构总览（本地 C/S 三进程）

```
┌────────────────────────────── 单台 Windows 机器 ──────────────────────────────┐
│                                                                              │
│  ┌─────────────────────┐        ┌───────────────────────────────┐            │
│  │  Electron 主进程     │ 启动/   │  Java 后端（Spring Boot）       │            │
│  │  · 窗口管理          │ 停止    │  · REST API（127.0.0.1:端口）  │            │
│  │  · 拉起/关闭后端     │ ──────▶ │  · 数据持久化（MySQL）         │            │
│  │  · 系统集成          │         │  · Git 操作（JGit/命令行）      │            │
│  └─────────┬───────────┘         │  · 搜索索引                    │            │
│            │                     └──────────────┬────────────────┘            │
│  ┌─────────▼───────────┐                        │  JDBC                        │
│  │  渲染进程（Web UI）  │     HTTP/JSON          │                              │
│  │  React + 画布引擎    │ ◀────────────────────▶ │                              │
│  │  （树状布局+自由画布）│                        │                              │
│  └─────────────────────┘              ┌─────────▼──────────┐                   │
│                                        │   MySQL 8.x（本地） │                   │
│                                        │   数据库 trailmind │                   │
│                                        └────────────────────┘                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**为什么是"三进程"而不是普通单进程应用？用大白话说：**

- **前端（Web UI）**：界面、画布、编辑体验全在浏览器技术里做——这是现代桌面应用的通行做法，界面开发效率最高，画布类库最丰富。
- **后端（Java）**：你指定的技术栈。它干"重活"：读写数据库、操作 Git 仓库、做搜索。它作为**本地服务**运行在电脑后台，前端通过本机地址（127.0.0.1）和它说话，不出网、不联网。
- **Electron 壳**：把 Web 前端"装进"一个桌面窗口，负责开机启动、把 Java 后端进程拉起来、关窗口时把它关掉。**为什么选 Electron 而不是别的壳？** 因为它是把 Web 前端变成 Windows 桌面程序最成熟、资料最多、踩坑案例最全的方案（Tauri 更轻但 Rust 生态相对新；对 vibecoding 而言，agent 对 Electron 的掌握程度普遍更高）。对你来说只需要知道：**界面是网页技术、逻辑在 Java、数据库是 MySQL，Electron 负责把它们打包成一个桌面软件**。

## 2. 技术选型与决策记录（ADR）

| 决策点 | 选定 | 备选 | 理由 |
|---|---|---|---|
| 桌面壳 | Electron（最新稳定版） | Tauri | Web 前端 + 本地服务的组合中 Electron 最成熟；Node 侧便于管理后端子进程 |
| 前端框架 | React 18 + TypeScript | Vue3 | 画布生态（React Flow）最成熟；TS 对 agent 协作更安全 |
| 构建工具 | Vite | CRA/Webpack | 快、配置简单、vibecoding 友好 |
| 状态管理 | Zustand | Redux | 轻量、样板少，适合中小应用 |
| 画布引擎 | React Flow（@xyflow/react） | 自研 canvas / 其他 | 自由画布开箱即用（拖拽/连线/缩放/自定义节点）；树状布局在其上自定义实现 |
| 树状布局算法 | 自研（简单递归分层布局） | 引入 mindmap 库 | 需求是"确定性、可控"的树布局，自研 200 行内可完成，避免受第三方布局限制 |
| Markdown 编辑 | CodeMirror 6 | 自研 textarea | 轻量、可扩展、编辑体验好 |
| 后端框架 | Java 17 + Spring Boot 3 | 原生 Java | Spring Boot 是 Java 生态事实标准，自动配置省心；Java 17 LTS |
| Git 操作 | JGit（Java 库） | 调命令行 git | JGit 纯 Java 免依赖；MVP 只读提交历史，JGit 足够。若遇疑难可回退命令行 |
| 数据库 | MySQL 8.x（本地实例） | SQLite/H2 | 用户指定 MySQL；本地实例由用户安装或 Docker 提供 |
| ORM | MyBatis-Plus | Spring Data JPA | SQL 可控、中文资料多、对 agent 友好 |
| 前后端通信 | REST（HTTP/JSON） | GraphQL/WebSocket | MVP 无高频实时需求；提交感知用轮询即可（见 §5） |
| 认证 | 无（仅绑定 127.0.0.1） | token | 回环地址不对外暴露，MVP 免鉴权；安全边界见 N6 |
| 全文搜索 | MySQL FULLTEXT + LIKE 兜底 | Elasticsearch/Lucene | 万级条目规模 MySQL 足够，零额外组件 |

## 5. 关键接口设计（REST，前缀 `/api/v1`）

> 完整接口清单由 M0 阶段在 backend 中落地并维护 OpenAPI 文档。此处给出核心接口契约，确保前后端与 agent 认知一致。

### 工作区
- `POST /workspaces` 创建（body: name, description?, repoPath?）
- `GET /workspaces` 列表（含统计：导图数、会话数）
- `GET /workspaces/{id}` 详情
- `PUT /workspaces/{id}` 更新
- `DELETE /workspaces/{id}` 删除（级联）

### 导图
- `POST /workspaces/{wid}/mindmaps` 新建
- `GET /workspaces/{wid}/mindmaps` 列表
- `GET /mindmaps/{id}` 整图数据（含 contentJson）
- `PUT /mindmaps/{id}` 保存整图（**整图覆盖写**，附 updatedAt 乐观锁）
- `PATCH /mindmaps/{id}` 重命名（PRD B4，body 仅 `name`；同步重算 search_text 的 name 部分，05 §4）
- `DELETE /mindmaps/{id}`
- `POST /mindmaps/{id}/export?type=PNG|OPML` （M4 任务三；响应 `data={filename, contentType, content}`：PNG content=Base64、OPML content=XML 原文；MD 属 P2 未实现，传 MD 返回 400）

### 会话与条目
- `POST /workspaces/{wid}/sessions` 开始会话
- `GET /workspaces/{wid}/sessions` 列表
- `GET /sessions/{id}` 详情（含条目分页，条目回填 tags 与 commits）
- `PATCH /sessions/{id}` （title/status/summary；置 completed 时记录 end_head 并追加 review 条目）
- `DELETE /sessions/{id}`
- `POST /sessions/{id}/entries` 追加条目（type, contentMd, tags?, commitHashes?）
- `PUT /entries/{id}` 编辑（MVP 仅 contentMd/type/tags）
- `DELETE /entries/{id}`
- `POST /entries/{id}/commits` 绑定提交（body: `{"commitHashes": ["<40位hash>", …]}`；幂等，已绑定 hash 跳过）
- `DELETE /entries/{id}/commits/{hash}` 解绑
- `GET /sessions/{id}/commits` 会话内全部绑定（entryId/commitHash/repoPath，供 Git 面板与「未绑定缓冲」计算）
- `GET /sessions/{id}/export/markdown` 导出会话为 Markdown（严格 06 §4，M3 总验收「导出→解析→比对」）
- `GET /sessions/{id}/export/json` 导出会话为 JSON（`trailmind-session-json` v1，06 §4A；时间为固定到秒的 ISO-8601 字符串）

### Git
- `GET /git/repo/status?path=` 校验路径是否为 git 仓库、返回 HEAD 信息（非法路径 400 明确提示，PRD C3.1）
- `GET /git/repo/commits?path=&since=&until=&limit=` 提交列表（hash/author/time/message/files；新→旧；limit 默认 50 上限 200；since/until 不可解析时忽略过滤，08 §10.4）
- `GET /git/repo/commits/{hash}?path=` 单个提交详情（PRD C3.5 详情弹层数据源；未知提交 404）
- `GET /git/repo/commits/{hash}/diff` 变更文件与 diff 预览（P1）

### 搜索与标签
- `GET /search?q=&type=&workspaceId=` 全局搜索（结果分 type: mindmap|entry|session；type 缺省 all；workspaceId 可选过滤；**M4 任务一落地**）
  - 响应 `data`：`{ query, mindmaps: [{id, workspaceId, workspaceName, name, snippet, nodeId, nodeCount, updatedAt}], entries: [{id, sessionId, workspaceId, workspaceName, sessionTitle, seq, type, snippet, createdAt}], sessions: [{id, workspaceId, workspaceName, title, status, startedAt, endedAt}] }`
  - 每类各 LIMIT 50；`snippet` 为命中词前后各 40 字符的纯文本片段（高亮前端做）；`nodeId` 为导图首个命中节点（跳转定位）
- `GET /tags?workspaceId=` 标签列表（含使用计数 entryCount；**M4 任务二落地**）
- `POST /tags` 创建（body: workspaceId, name；工作区内重名 400）｜ `PUT /tags/{id}` 重命名（经 tag.id 引用全局生效）｜ `POST /tags/{id}/merge` 合并（body: targetId；条目重挂目标后删源，事务内）｜ `DELETE /tags/{id}`（级联清 entry_tag）
- `GET /entries?tagId=&sessionId=` 按标签筛条目（tagId 必传，sessionId 可选会话内过滤；响应含 sessionTitle/workspaceName/tags，按会话开始时间倒序 + seq 正序，LIMIT 500；**M4 任务二落地**）

### 系统
- `GET /health` 健康检查（Electron 启动时轮询）
- `POST /shutdown` 优雅关闭（Electron 退出时调用，触发 Spring 上下文关闭并结束 JVM）
- `GET /settings` ｜ `PUT /settings` 应用设置（**M4 任务四落地**）
  - `GET` 响应 `data`：`{ theme: light|dark|system（默认 system）, defaultRepoPath: string|null, database: { host, port, database, username, passwordConfigured } }`——数据库连接为只读展示，密码不回传（只给是否已配置）
  - `PUT`（PATCH 语义，null 字段不改动）body：`{ theme?, defaultRepoPath? }`；theme 非法 400；defaultRepoPath 传空白字符串表示清除，非空时须为含 `.git` 目录的真实路径（否则 400）
  - 持久化于 `setting` 表（k/v：`theme`、`default_repo_path`）；**会话创建仓库回退链**：会话级 → 工作区设置 → 全局默认仓库路径（04 §6.6）
- `POST /backup/export` 全量备份导出（**M4 任务六落地**）：导出全部 8 张表为「trailmind-backup」v1 JSON 压缩包（zip 内 `trailmind-backup.json`，JDK 内置 ZipOutputStream 零依赖），响应 `data={filename, contentType: application/zip, content}`（content 为 Base64）；协议与 06 §4A 同风格（format/version/exportedAt + 时间固定到秒），供 P2 导入恢复

## 6. 关键技术设计决策

### 6.1 保存策略
- 导图：**整图防抖保存**（内容变化后 800ms 无操作即 PUT），携带 `updatedAt` 乐观锁；冲突时提示"本地与他人修改冲突"（单机场景极少发生，防御性实现）
- 条目：**即时保存**（提交即写库，事务）
- 后端对写操作统一事务；前端保存失败 toast + 重试按钮

### 6.2 Git 提交感知
- 会话激活期间，前端每 5s 调 `GET /git/repo/commits?since=<会话开始时HEAD>`，发现新提交 → 存入「未绑定提交」缓冲 → 触发 UI 建议卡片
- 「未绑定」= 会话区间提交中未被任何条目绑定的部分（对照 `GET /sessions/{id}/commits`）
- 建议卡片一键「绑定到最近条目」/「忽略」；**同一会话最多提醒 3 次**（07 §6），已忽略批次不再重复提醒，配额按会话持久化（localStorage，强杀重启不重置）
- 会话结束时记录终止 HEAD；下次打开会话可"继续检测"（completed 会话打开时拉取一次，不再轮询）
- 性能：仅读取 commit 元信息，不读 diff，开销可忽略；轮询有防重叠保护（在途请求时跳过本轮）

### 6.3 搜索实现（M4 任务一落地）
- 条目（`entry.content_md`）与导图（`mindmap.search_text`）建 FULLTEXT 索引（ngram 解析器，支持中文）
- 查询策略（`SearchQueryUtil.analyze`）：空白分词 + 剔除布尔运算符；**任一词 <2 字符**（中文单字/单字符——`ngram_token_size=2` 无 unigram token，实测 FULLTEXT 必 0 命中）**整体降级 LIKE 兜底**（09 R4 缓解）；否则 FULLTEXT 布尔模式 `+词1 +词2`（AND 语义，规避自然语言模式 50% 常见词规则漏配）
- 会话标题无 FULLTEXT 索引，恒走 LIKE（tokens OR 子串；标题 ≤200 字符 × 千级行代价可忽略，05 §6 ADR）
- 结果按类型分组返回，前端分 Tab 展示；片段由后端生成（命中词前后各 40 字符），**关键词高亮由前端做**（<mark> 渲染）
- 同 (q, type, workspaceId) 结果缓存 30s（04 §8）；容量 500 键防膨胀
- 规模警戒线：单库条目 >10 万条时再评估引入 Lucene（记录在 09 风险文档）

### 6.4 双模式导图的数据与渲染
- **数据层统一**：一张导图 = 一份 JSON（nodes[] + edges[]），节点含 `layout`（tree 模式下为 null，canvas 模式下为 x/y）与 `style`（color/shape/bold）
- **树状模式**：后端/前端运行自研布局算法计算坐标（不落库），节点间为父子关系（edge 类型 `parent-child`）
- **画布模式**：直接使用节点坐标与任意连线（edge 类型 `free`）
- **切换规则**（对应 PRD B3.3）：
  - 树→画布：布局结果平铺为坐标，全部保留
  - 画布→树：边集构成严格树（每节点至多一父、无环）→ 按树布局；否则弹三选一（忽略非树边 / 保持画布 / 仅重排树形部分）
- 布局算法：递归计算子树高度 → 中序均分 → O(n) 复杂度；子节点默认水平排列（右向树），支持"向左/向右"整体镜像（P1）

### 6.5 进程生命周期与异常恢复
- 启动：Electron main → spawn `java -jar backend.jar`（端口取自设置，默认 17860）→ 轮询 /health（最长 10s）→ 加载窗口
- 退出：before-quit → POST /shutdown（优雅）→ 等待进程退出（3s 超时）→ 强杀兜底
- 崩溃恢复：MySQL 事务保证写入原子；导图整图保存失败不产生半写；重启后前端检测 `updatedAt` 与本地缓存差异（MVP 简单处理：以后端为准）
- 端口占用：启动时若端口被占且非本应用 → 报错并给出提示；是本应用残留进程 → 先杀再起

### 6.6 配置管理（M4 任务四落地）
- 设置存 MySQL `setting` 表（k/v）+ 前端缓存（Zustand 启动加载）；数据库连接串存 `desktop/config.json`（加密可后置，MVP 仍为 .env 注入 DB_USER/DB_PASS）
- 设置页三项：**数据库连接信息展示**（只读，host/port/库名/用户名/密码是否已配置，密码不回传）、**主题切换**（light/dark/system 三选一，默认 system 跟随系统；前端写 `<html data-theme>` 切换 CSS 变量，切换乐观应用、落库失败回滚）、**默认仓库路径**（全局回退值，须为含 .git 目录的真实路径）
- 会话创建仓库回退链：**会话级 repoPath → 工作区 repo_path → 全局默认仓库路径**（新会话未指定时逐级继承，PRD C1.1）
- 首次启动引导：探测本机 MySQL（127.0.0.1:3306）→ 输入账号密码 → 自动执行 schema.sql（幂等：CREATE TABLE IF NOT EXISTS）

### 6.7 导出实现（M4 任务三落地）
- **统一响应**：导出端点仍走 `{code,data,message}` 包裹，不破坏 08 §4.2。会话 JSON 的 `data` 为结构化对象；导图导出 `data={filename, contentType, content}`，其中 PNG content 为 Base64、OPML content 为 XML 原文，前端解码后经 Blob 下载。
- **会话 JSON**：与 Markdown 导出共用 `EntryService.page` 全量数据源，两种格式内容一致；时间用固定秒级的 ISO-8601 字符串（`LocalDateTime.toString` 在秒为 0 时会省略秒，机器协议需形态稳定）。
- **导图 PNG**：Java2D 无第三方依赖。节点有 `layout` 坐标用画布坐标，无坐标用与前端 `treeLayout.ts` 同构的右向树布局兜底（层距 200 / 行距 64）；折叠状态导出时忽略以保证「整图」完整；绘制父链边（由 parentId 派生）与自由边（虚线箭头）。超宽/超高导图整体等比缩放至最长边 4096px，内容不裁剪、防极端数据撑爆内存。颜色板与 03 §6 一致。
- **导图 OPML**：层级由 `nodes[].parentId` 派生（05 §4「树边不落库」），输出 OPML 2.0；`text` 必填属性 + `_note`（节点备注）+ `category`（节点标签逗号连接）。自由连线无法用 OPML 表达，导出时忽略（文档同步说明，不视为数据丢失——自由边仍在 content_json）。
- **文件名安全**：后端对导图名做 Windows 非法字符清理并返回完整文件名；前端对会话标题做同一规则清理（`utils/download.ts`），两端规则保持一致。
- **前端导出前先保存**：导图导出会先保存 `dirty` 内容，失败则不导出，避免产物与画布不一致。
