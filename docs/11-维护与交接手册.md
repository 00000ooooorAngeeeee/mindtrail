## 1. 产品是什么

思迹 TrailMind = Windows 桌面端工具 = **双模式思维导图 + Git 绑定的 vibecoding 过程记录**。
- 工作区（=一个项目）承载：多张导图（树状/自由画布双模式）、多个记录会话（时间线条目）、工作区级标签
- 全局能力：全文搜索、标签管理、导出（Markdown/JSON/PNG/OPML/全量备份）、设置（主题/仓库路径）
- 产品用自己记录开发过程（dogfooding，06 规范），记录存于工作区「TrailMind 开发」
- 里程碑进度：M0 骨架 → M1 工作区+树状导图 → M2 自由画布 → M3 过程记录+Git 绑定 → M4 搜索/标签/导出/打磨 → **v1.1 P1 全部完成**（联动/连线标签/补记插入/diff 预览/标签云/自适应缩放/多会话并行视图）
- 当前下一任务：v1.2 / P2「导入恢复」（07 §8 Backlog）

## 2. 总体架构

```
┌────────────────────────── 单台 Windows 机器 ──────────────────────────┐
│                                                                       │
│  ┌─────────────────────┐       ┌──────────────────────────────┐      │
│  │ Electron 主进程      │ 拉起/ │ Java 后端（Spring Boot）       │      │
│  │ 窗口 + 后端进程管理   │ 停止  │ REST API 127.0.0.1:17860      │      │
│  │ (desktop/main)      │─────▶│ (backend, 仅回环 N6)          │      │
│  └─────────┬───────────┘       └──────────────┬───────────────┘      │
│            │  HTTP/JSON（相对路径 /api/v1）     │  JDBC                │
│  ┌─────────▼───────────┐       ┌──────────────▼───────────────┐      │
│  │ 渲染进程（Web UI）    │◀────▶│  MySQL 8.x（库 trailmind）     │      │
│  │ React + React Flow  │       │  9 张表，schema.sql 幂等建表   │      │
│  └─────────────────────┘       └──────────────────────────────┘      │
└──────────────────────────────────────────────────────────────────────┘
```

- **开发态链路**：`npm run dev`（scripts/dev.mjs）= mvn spring-boot:run（后端）+ Vite（前端 http://localhost:5173）；Electron dev 态加载 5173（TRAILMIND_DEV_URL 可覆盖）
- **生产态链路**：Electron 打包后 → 主进程拉起 `resources/backend/trailmind-backend-0.0.1.jar`（extraResources）→ 窗口加载 asar 内 `frontend/dist`
- **数据流要点**：导图整图 JSON 存取（content_json 一图一行）；条目/会话/标签严格表化；Git 只读（JGit，不落库仅存 hash）；搜索走 FULLTEXT(ngram)+LIKE 兜底；全部写操作后端事务化
- **目录结构**（04 §3）：`backend/`（Spring Boot）｜ `frontend/`（React+Vite）｜ `desktop/`（Electron 壳）｜ `scripts/`（开发/验收脚本）｜ `docs/`（文档集 01-12 + CHANGELOG）

## 5. 版本号管理（改版本号必读）

当前全库版本 0.0.1。**改版本号必须同步 6 处**（漏改 = 产物版本不一致或打包失败）：

| # | 位置 | 作用 |
|---|---|---|
| ① | `backend/pom.xml` `<version>` | 决定 jar 文件名 `trailmind-backend-0.0.1.jar` |
| ② | `backend/.../controller/HealthController.java` **硬编码字符串** `"0.0.1"` | /health 返回的版本号，**不与 pom 联动，最易漏改** |
| ③ | `frontend/package.json` version | 前端包版本（产物无关，保持同步即可） |
| ④ | `desktop/package.json` version | 决定 NSIS 安装包名 `TrailMind-Setup-${version}.exe` |
| ⑤ | `desktop/main/index.js` 两处 jar 名（`DEV_JAR` 与 `loadBackendJarPath` 的 `trailmind-backend-0.0.1.jar`） | 硬编码，改 jar 名必须同步 |
| ⑥ | `desktop/electron-builder.yml` extraResources 的 from/to 两处 jar 名 | 同上 |

> 若未来 jar 名稳定为 `trailmind-backend.jar` 可消除 ⑤⑥ 的耦合（当前未做，属已知改进点）。

**协议版本**（与产品版本号独立，变更协议时必须升，见 §8）：会话 Markdown `trailmind-session` v1、会话 JSON `trailmind-session-json` v1、全量备份 `trailmind-backup` v1、content_json 结构 v1。

## 6. 发布与更新已安装的产品

**发布流程**：
1. 完成功能 + 单测全绿 + `npm run verify` ALL PASS + 文档同步（07 勾选 + AGENTS.md）
2. 按 §5 升版本号（6 处）
3. `npm run package` → 产出 `release/TrailMind-Setup-<版本>.exe`
4. 在干净 Windows 上安装验证（N4 启动计时参考 04 §8；**正式 N4 验收仍是环境待办**，需开启 Windows 开发者模式）

**更新已安装产品（升级安装）**：
- electron-builder NSIS 为覆盖式安装：新版本安装包直接覆盖旧版本（允许更换安装目录）。Windows 会保留用户已装版本的快捷方式并替换程序文件
- **数据不随升级丢失**：全部业务数据在 MySQL（库 trailmind），不在安装目录；卸载/升级均不影响数据库
- **schema 兼容**：启动时 `spring.sql.init.mode: always` 幂等执行 schema.sql（CREATE TABLE IF NOT EXISTS），新版本新增的表/列会自动补齐；**旧版本不支持新增列**（schema.sql 用 ALTER 演进，见 §7）
- **配置文件**：数据库连接串在 `resources/.env`（打包时从仓库根 .env 带入）；升级覆盖 .env 前请备份本地修改（当前 MVP 无此 UI）
- **回滚**：安装旧版本安装包即可回滚；数据库无需迁移（无破坏性变更约定）
- **数据备份/恢复**：升级前建议在设置页「数据备份」导出全量备份 zip（trailmind-backup v1）；v1.2 P2 起设置页「数据恢复」可从 zip 全量恢复（POST /backup/import，事务清空 9 表+按原 id 回填，不可撤销）

## 7. 数据库与 schema 演进

- 9 张表：`workspace / mindmap / session / entry / tag / entry_tag / entry_commit / node_entry / setting`
- schema 权威定义：`docs/05 §3`；落库脚本：`backend/src/main/resources/db/schema.sql`（幂等 CREATE TABLE IF NOT EXISTS）
- **铁律**：① 表结构变更必须同步 schema.sql（08 §4.4）；② **不删列**（用 ALTER 演进，保留兼容）；③ 外键不用物理 FK，级联删除在 Service 层显式处理（05 §3）
- 关键索引：entry(session_id, seq)、mindmap FULLTEXT(search_text) ngram、entry FULLTEXT(content_md) ngram、node_entry(entry_id) 反向索引
- 搜索注意：`ngram_token_size=2` 无 unigram token，**单字必须走 LIKE 兜底**（SearchQueryUtil.analyze 自动判定，改动搜索逻辑时勿破坏该降级路径）
- 数据规模参考（05 §7）：单人使用条目 <2 万；10 万条警戒线后再评估 Lucene

## 13. 常见问题速查（历史踩坑）

| 现象 | 原因与解法 |
|---|---|
| `mvn test` 18 个 @SpringBootTest 报 Access denied | DB_PASS 未注入进程：先加载根 `.env` 再跑（`process.loadEnvFile` 不会自动发生在 mvn） |
| vitest / vite / verify / Electron 报 `spawn EPERM` | 沙箱禁止命名管道子进程（esbuild/mysql/git/Electron）：需全权限运行（用户批准） |
| Electron 启动崩溃 `FATAL: platform_channel` | 沙箱对 %APPDATA% 只读：加 `--user-data-dir=D:\...\.electron-dev`（已 gitignore） |
| 改了后端代码但接口行为不变 | Electron 拉起的是 `target/trailmind-backend-0.0.1.jar`：**改后端后必须 `mvn package` 重建 jar** 再启（真实踩过） |
| 17860 端口被占 | 本应用残留进程会被 Electron kill-and-spawn；非本应用（如 mvn spring-boot:run 与 Electron 二选一）报错提示 |
| 组件 `undefined`（Element type is invalid） | Windows 大小写不敏感：同目录 `TagCloud.tsx` 与 `tagCloud.ts` 冲突 → 纯函数改名 tagCloudUtil.ts。**同目录避免仅大小写区分的文件名** |
| datetime-local 秒为 0 时输入值丢 `:00` | jsdom/浏览器归一化；断言用正则容忍，提交时状态值带秒（datetimeLocalToIso 自动补） |
| JGit `DiffFormatter.scan` 编译不过 | 需要 `AbstractTreeIterator`：用 `new CanonicalTreeParser(null, reader, tree)` + ObjectReader 显式关闭 |
| MySQL 中文乱码（脚本） | mysql CLI 加 `--default-character-set=utf8mb4` |
| FULLTEXT 中文单字搜不到 | ngram_token_size=2 无 unigram：SearchQueryUtil 自动降级 LIKE，勿绕过 |
| 导出文件名乱码/非法 | sanitizeFileName 前后端同规则（Windows 非法字符→_） |
| 请求挂起永久 loading | client.ts 10s AbortController 超时（-2）；若改超时注意入口防重 |
| 搜索跳转不闪烁 | 跳转经 seq 估算分页 + highlightHandledRef 只处理一次；删除造成 seq 空洞可能偏移（静默忽略属预期） |
| 会话结束后无法追加普通条目 | PRD C1.3 语义：仅 review/note（400 提示）；补录 artifact 类内容用 note 并注明 |
| 重命名工作区后列表「导图 0 · 会话 0」需进工作区才刷新 | `update` 响应经 `selectById` 不填充 `mindmapCount/sessionCount`（@TableField(exist=false)）→ 前端整对象替换使列表归零；已改 `selectWithCounts` 返回带计数 + 前端 `rename` 合并 `?? w.mindmapCount` 保留（07 §19） |
| 第三次进入导图适应视图失效、导图停在左上角 | **已修复（07 §19 修复二，提交 69f1954）**。GUI 实机打点证实根因（取代此前「假设未证实」）：`InitialFitController` 主路径 effect 依赖 `useNodesInitialized`，内容 effect 每次 `setNodes(buildNodes)` 重建节点对象使 `adoptUserNodes` 重置 `measured` → `useNodesInitialized` 翻 false → effect 清理 `cancelAnimationFrame` 掉已排程的双 rAF `fitView`，且 `doneKey` 已置位阻断重排与 800ms 兜底（是否失效取决于 outer rAF 与 cleanup 的子帧竞态，约第三次起连接预热后 links 2 帧内返回时复现）。打点亦证 `measured` 确经 ResizeObserver 回填（0/11→11/11 约4ms），故上一会话 `carryMeasured` 前提错误、反致首开失效。修复：主路径改 rAF 轮询 `rf.getNodes()` measured，全部测量完成即一次性 `fitView`（effect 不再依赖 `useNodesInitialized`，重建翻 false 不再取消已排程拟合）。jsdom 无法复现（无真实布局），须 Electron+CDP 多次进入取证 |
