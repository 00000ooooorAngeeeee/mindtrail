**三进程（Electron + React 前端 + Java 后端 + MySQL）全链路跑通**：能启动、能连通、能建表、能落一条数据。M0 结束时你拥有一个可安装的 Windows 桌面应用骨架，且为 M1（导图）备好数据层。

## 3. 任务 0.0 · 环境准备（一次性，约 30 分钟）

**目标**：开发环境就绪，避免后续任务被环境问题卡住。

**实施步骤**：
- [ ] 安装/确认：Node.js ≥ 20 LTS、JDK 17（配置 `JAVA_HOME`）、Maven 3.9+、Git、MySQL 8.x
- [ ] MySQL：确认服务可连（`mysql -u root -p`）；记录账号密码（后续写入后端配置）
- [ ] 验证 Node/Java/Maven 版本命令可用
- [ ] 确认网络（npm / Maven Central 可达；若受限，准备镜像源配置）

**验收清单**：
- [ ] `node -v` / `java -version` / `mvn -v` / `mysql --version` 全部可用
- [ ] `mysql -u<user> -p<pass> -e "SELECT 1"` 返回 1

**常见坑**：MySQL 8 默认认证插件 `caching_sha2_password` 对旧驱动不兼容——后端连接串必须带 `allowPublicKeyRetrieval=true&useSSL=false`（见任务 0.3）；JDK 必须是 17（Spring Boot 3 不支持 8/11 以下）。

## 5. 任务 0.2 · 后端 Spring Boot 骨架 + /health

**目标**：Java 后端可独立启动，提供健康检查接口，为前端连通性提供验证锚点。

**实施步骤**：
- [ ] 在 `backend/` 创建 Spring Boot 3 工程（可用 [Spring Initializr](https://start.spring.io/) 生成或手写 pom）：依赖 `spring-boot-starter-web`、`mybatis-plus-boot-starter`、`mysql-connector-j`、`lombok`（可选）、`spring-boot-starter-test`
- [ ] 包结构：`com.trailmind.backend`，子包 `controller/ service/ repository/ entity/ config/ git/`
- [ ] `application.yml`：
  ```yaml
  server:
    port: 17860
    address: 127.0.0.1        # 仅回环，安全边界 N6
  spring:
    datasource:
      url: jdbc:mysql://127.0.0.1:3306/trailmind?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai&characterEncoding=utf8
      username: ${DB_USER:root}
      password: ${DB_PASS:}
  mybatis-plus:
    configuration:
      map-underscore-to-camel-case: true
  ```
  （数据库连接在任务 0.3 激活，0.2 阶段可注释 datasource 保证启动不依赖 MySQL）
- [ ] `HealthController`：`GET /api/v1/health` → `{ "code":0, "data":{ "status":"ok", "app":"trailmind", "version":"0.0.1" }, "message":"ok" }`（统一响应结构，08 §4.2）
- [ ] 统一响应类 `ApiResponse<T>`（code/data/message）+ 全局异常处理 `@RestControllerAdvice`
- [ ] 单测：`HealthControllerTest`（MockMvc 断言 code=0）

**验收清单**：
- [ ] `mvn spring-boot:run` 启动成功，`curl http://127.0.0.1:17860/api/v1/health` 返回上述结构
- [ ] `netstat -ano | findstr 17860` 显示监听地址为 127.0.0.1
- [ ] 单测通过（`mvn test`）

**常见坑**：端口被占（排查占用进程）；Spring Boot 3 需 Java 17+；MyBatis-Plus 与 Spring Boot 3 需用 `mybatis-plus-spring-boot3-starter`（而非旧版 starter）。

**建议提交**：`feat(backend): 后端骨架与健康检查接口`

## 6. 任务 0.3 · MySQL 连接 + 幂等建表

**目标**：应用自动建库建表（05 §3 全表），重复启动不报错。

**实施步骤**：
- [ ] 将 05 §3 的建表脚本落为 `backend/src/main/resources/db/schema.sql`（全 8 表：workspace/mindmap/session/entry/tag/entry_tag/entry_commit/setting）
- [ ] 实现 `DatabaseInitializer`（`ApplicationRunner`）：启动时
  1. 连接 MySQL（不指定库）执行 `CREATE DATABASE IF NOT EXISTS trailmind DEFAULT CHARACTER SET utf8mb4`
  2. 切换到 trailmind 库，执行 schema.sql（`CREATE TABLE IF NOT EXISTS` 天然幂等）
- [ ] 激活 0.2 中注释的 datasource 配置；`DB_USER/DB_PASS` 走环境变量，缺省 root/空
- [ ] 单测：`SchemaInitializerTest`——对空库执行两次初始化均无异常（可用 Testcontainers MySQL 或本机 MySQL 测试库；若 CI 无 MySQL，标记 `@Disabled` 并人工验证）

**验收清单**：
- [ ] 清空 trailmind 库后启动 → 自动建全表；再次启动无任何错误
- [ ] `SHOW TABLES` 可见 8 张表；`SHOW CREATE TABLE entry` 含 `FULLTEXT ... WITH PARSER ngram`
- [ ] 库/表字符集均为 utf8mb4

**常见坑**：`serverTimezone` 不配会报时区错误（已写入 URL）；MySQL 8 的 ngram 全文索引只在 InnoDB 生效；连接串缺 `allowPublicKeyRetrieval` 会报公钥检索错误。

**建议提交**：`feat(backend): 数据库连接与幂等建表`

## 8. 任务 0.5 · 前端工程 + 首页连通

**目标**：React 前端能调通后端 API 并展示数据——"前后端连通"的可见证明。

**实施步骤**：
- [ ] 在 `frontend/` 用 Vite 创建 React + TS 工程（`npm create vite@latest . -- --template react-ts`）
- [ ] 依赖：`zustand`；`axios` 或原生 fetch 封装 `src/api/client.ts`（baseURL `http://127.0.0.1:17860/api/v1`，统一解包 `{code,data}`，code≠0 抛错）
- [ ] `src/api/health.ts`、`src/api/workspaces.ts`（GET health / GET/POST workspaces）
- [ ] 首页 `App.tsx`：品牌名"思迹 TrailMind" + 后端版本号（来自 /health）+ 工作区列表（来自 /workspaces，空态提示"暂无工作区"）+ 一个"创建测试工作区"按钮（验证 POST）
- [ ] CORS 处理二选一：后端加 CORS 配置允许 `http://localhost:5173`，或 Vite dev proxy 转发 `/api` → 127.0.0.1:17860（**推荐 proxy**，生产无 CORS 问题）
- [ ] 单测：`client.test.ts`（mock fetch 验证解包与错误分支）、`App.test.tsx`（mock API 渲染品牌名）

**验收清单**：
- [ ] `npm run dev` 后浏览器打开首页：显示品牌名、后端版本、工作区列表
- [ ] 点击创建按钮 → 列表出现新工作区（刷新不丢）
- [ ] 后端未启动时首页显示明确错误态（而非白屏）
- [ ] 单测通过

**常见坑**：CORS 未配（用 proxy 规避）；中文乱码（前端文件 UTF-8、后端响应 charset 已由 Spring 处理）；fetch 失败无提示。

**建议提交**：`feat(frontend): 前端工程骨架与后端连通首页`

## 9. 任务 0.6 · Electron 壳（进程生命周期）

**目标**：桌面窗口 + 自动拉起/关闭 Java 后端，形成完整"产品形态"。

**实施步骤**：
- [ ] 在 `desktop/` 建 Electron 工程：`main/`（主进程，TS 或 JS）+ `preload/`（预留）
- [ ] 主进程要点（对应 04 §6.5）：
  - `app.requestSingleInstanceLock()`：第二实例直接 focus 已开窗口
  - 窗口：1280×800、min 尺寸 960×600、title"思迹 TrailMind"、加载 Vite dev URL（开发）或打包产物（生产）
  - 后端进程管理模块 `backend-process.js`：
    - `start()`：`spawn('java', ['-jar', backendJarPath])`；先探端口 17860：若被占用 → 查占用进程命令行是否含 `trailmind`（本应用残留）→ 是则 `taskkill /PID <pid> /T /F` 后启动；否则提示"端口被其他程序占用"
    - 健康等待：轮询 `GET /api/v1/health`（500ms 间隔，最长 10s），期间窗口显示"正在启动后端…"遮罩
    - `stop()`：`app.on('before-quit')` → `POST /api/v1/shutdown`（后端新增 `ShutdownController` 触发 `SpringApplication.exit`）→ 等待退出 3s → 超时 `taskkill /PID /T /F` 兜底
  - 后端 jar 路径：开发期 `backend/target/trailmind-backend-0.0.1.jar`；打包期随 electron-builder extraResources 携带
- [ ] 单测：`backend-process.test.ts`（mock spawn/taskkill 验证分支逻辑——重点测"端口被本应用残留占用"分支）
- [ ] 联调：完整启动/退出流程

**验收清单**：
- [ ] `npm run dev:desktop`：窗口出现 → 遮罩 → 后端自动拉起 → 首页连通
- [ ] 关闭窗口：Java 进程自动退出（`tasklist | findstr java` 无残留）
- [ ] 启动两个实例：第二个不重复拉后端
- [ ] 模拟残留（手动起 java -jar）：启动应用自动清理后正常使用
- [ ] 单测通过

**常见坑**：Windows 下 `spawn('java')` 找不到 → 读 `JAVA_HOME` 拼接路径；`taskkill` 必须带 `/T`（杀子进程树）；Electron 开发时窗口加载 Vite URL 需等 dev server 就绪。

**建议提交**：`feat(desktop): Electron 壳与后端进程生命周期管理`

## 10. 任务 0.7 · 一键脚本与打包

**目标**：`npm run dev` 一键开发、`npm run package` 产出可安装 exe、`scripts/verify` 冒烟自检。

**实施步骤**：
- [ ] `scripts/dev.mjs`（Node 脚本，Windows 兼容）：并行启动后端（`mvn spring-boot:run`）与前端（`npm run dev`）；Ctrl+C 时全部终止
- [ ] `scripts/verify.mjs` 冒烟脚本（M0 验收自动化的核心）：依次断言
  1. 后端 /health 返回 code=0
  2. schema 表齐全（连 MySQL 查 information_schema）
  3. POST /workspaces 创建成功 → GET 列表可见 → DELETE 清理
  4. 输出 `M0 SMOKE: ALL PASS`
- [ ] 根 `package.json` scripts 接通：`dev`、`build`（前端 build + 后端 jar）、`package`（electron-builder）、`verify`
- [ ] electron-builder 配置：`desktop/electron-builder.yml`——NSIS 目标、应用名"思迹 TrailMind"、后端 jar 放 `extraResources`、安装后启动脚本（保证 jar 路径解析）
- [ ] 打包验证：`npm run package` 产出 exe；安装运行

**验收清单**：
- [ ] 全新环境 `npm install` + `npm run dev` 一键可用
- [ ] `node scripts/verify.mjs` 全绿输出 `ALL PASS`
- [ ] 安装包产出；安装后双击 → 3s 内可交互（N4 计时）；卸载/强杀无残留进程
- [ ] 开发机重复执行 dev/stop 三次无端口冲突

**常见坑**：Windows 下 spawn 命令用 `cmd /c` 包裹 npm/mvn；electron-builder 下载依赖慢（国内镜像配置）；打包后 jar 路径含空格（用 `path.join(process.resourcesPath, ...)`）。

**建议提交**：`chore: 一键开发脚本、打包与验收冒烟`
