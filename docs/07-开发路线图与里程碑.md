# 07 · 开发路线图与里程碑

> 版本：v0.1 ｜ 状态：已定稿 ｜ 依据：PRD 02（优先级） ｜ 面向：开发排期、vibecoding agent

## 1. 总览

```
M0 骨架 ──▶ M1 工作区+树状导图 ──▶ M2 自由画布 ──▶ M3 过程记录(Git绑定) ──▶ M4 搜索/标签/导出/打磨
(1-2次会话)   (3-4次会话)           (2-3次会话)     (3-4次会话)              (2-3次会话)
```

- 每个里程碑结束都必须通过该里程碑的**验收清单**，才进入下一个
- 每个里程碑预计 1-4 次 vibecoding 会话；**一次会话只做一个里程碑内的小任务**，不跨里程碑
- 每次会话结束，按 [06-过程记录规范](06-过程记录规范.md) 在本产品（或其前置形态）中记录过程——**从 M0 起 dogfooding（吃自己的狗粮）**

## 2. 通用完成定义（DoD，每个任务适用）

- [ ] 功能按 PRD 对应需求实现
- [ ] 相关 NFR（性能/可靠性）验证通过
- [ ] 关键逻辑有单元测试（后端 service / 前端纯函数）
- [ ] 文档同步更新（04/05 架构数据模型变化、06 记录规范变化）
- [ ] 数据库 schema 变化已同步到 schema.sql
- [ ] 提交信息符合 08 文档提交规范

## 3. M0 · 项目骨架与工程化

**目标**：三进程（Electron + React 前端 + Java 后端 + MySQL）全链路跑通，能启动、能连通、能建表。

**任务清单**：
- [ ] 仓库初始化（目录结构按 04 文档 §3；git init + README）
- [ ] 后端：Spring Boot 工程，`GET /health` 返回 `{status:"ok",version:"0.0.1"}`
- [ ] 后端：MySQL 连接 + 执行 schema.sql（幂等，首次启动自动建库建表）
- [ ] 后端：workspace CRUD 基础接口（仅创建/列表）
- [ ] 前端：Vite + React + TS 工程，首页显示"思迹 TrailMind"与后端版本号（验证连通）
- [ ] Electron：主进程拉起/关闭后端 jar；窗口加载前端；端口冲突处理（04 文档 §6.5）
- [ ] 开发脚本：一键启动（dev 模式前后端联调）、一键打包（electron-builder NSIS）
- [ ] dogfooding 准备：建立本仓库自己的"开发记录"约定（首次会话即用 06 规范记录）

**验收清单（全部通过才算 M0 完成）**：
- [x] `npm run dev` 一键拉起前后端（后端 /health + 前端 dev server 均验；Ctrl+C 树杀复用已单测的 killProcessTree）
- [ ] 双击打包后的 exe 安装、启动到可交互 ≤ 3s（N4）—— **环境待办：需先开启 Windows 开发者模式（见 docs/10 §10），再人工安装计时验收**
- [x] MySQL 首次启动自动完成建库建表；重复执行 schema.sql 无报错
- [x] `GET /health` 可被 curl 调用；端口仅绑定 127.0.0.1（N6）
- [x] 创建/列表工作区通过 API 可用，数据落库可查
- [x] 强杀应用后重启，无残留 java 进程（或可自动清理）
- [x] 本文档集已纳入仓库并链接到 README

## 4. M1 · 工作区 + 树状思维导图

**目标**：能建工作区、画一张可用的树状导图（增删改、拖拽、折叠、自动布局），数据持久化。

**任务清单**（对应 PRD 模块 A、B1、B4）：
- [x] 工作区：完整 CRUD + 工作区首页（详情/更新/级联删除；导图/会话列表暂空态、待数据层，统计已带出）
- [x] 导图数据层：content_json 存取、search_text 维护、node_count 统计（05 文档 §3/§4）
- [ ] 树状模式画布：
  - [ ] 节点渲染（圆角卡片、选中态、浮动工具条）
  - [ ] 添加/编辑/删除节点（含子树删除确认）
  - [ ] 拖拽改层级（悬停高亮、根区变分支）
  - [ ] 折叠/展开 + 节点徽标
  - [ ] 自研树布局算法（04 文档 §6.4；O(n)、无重叠）
  - [ ] 缩放/平移/适应视图、双击空白加节点
- [ ] 撤销/重做（导图操作）
- [ ] 整图防抖保存（800ms）+ 乐观锁

**验收清单**：
- [ ] 新建工作区 → 新建导图 → 完成"添加 20 个节点 + 拖动 5 次 + 折叠 2 处"全程无卡顿（≤100ms/操作，N1）
- [ ] 布局无节点重叠、层级清晰；折叠后布局正确收缩
- [ ] 刷新/重启应用后导图完整恢复
- [ ] 500 节点压力测试：缩放平移 ≥45fps（N1）
- [ ] 撤销/重做覆盖节点增删改与层级变化
- [ ] 删除含子树的节点有确认且可撤销
- [ ] 搜索可命中导图节点文本（search_text 生效，提前验证 M4 依赖）

## 5. M2 · 自由画布模式（双模式）

**目标**：同一张导图可切画布模式：自由摆放、任意连线、框选、样式；双模式切换数据一致。

**任务清单**（对应 PRD B2、B3）：
- [ ] React Flow 接入：节点/边渲染、拖拽、连线、缩放平移
- [ ] 节点形状（圆角矩形/矩形/椭圆/菱形）+ 颜色
- [ ] 画布模式 layout 坐标持久化（写入 content_json）
- [ ] 模式切换：
  - [ ] 树→画布：布局结果平铺
  - [ ] 画布→树：严格树判定 + 三选一处理（PRD B3.3）
- [ ] 框选多选、批量删除/移动（P1 项提前或后置，按进度）
- [ ] 自由便签（无文本纯形状，P1 项）

**验收清单**：
- [ ] 树状模式画的图切到画布后位置合理，可自由拖动任意节点
- [ ] 画布中新增自由连线后切回树状：非树边被正确提示并按选择处理
- [ ] 两模式间增删改互相同步（B3.4）
- [ ] 坐标/形状/颜色持久化，重启不丢
- [ ] 框选/批量操作正常（若本轮未做，明确记录为 P1 遗留）

**任务清单**（对应 PRD 模块 C）：

- [ ] 条目：追加（类型+Markdown+标签）、编辑、删除、seq 管理

## 9. 里程碑依赖与风险速查

| 依赖 | 说明 |
|---|---|
| M1 依赖 M0 的 API 链路与 schema | 数据库先行 |
| M2 依赖 M1 的 content_json 数据层 | 双模式共享数据 |
| M3 的 Git 绑定依赖 M0 的仓库初始化 | 本仓库即 dogfooding 对象 |
| M4 搜索依赖 M1 的 search_text 维护 | 已在 M1 提前实现 |

| 风险 | 缓解 |
|---|---|
| 树布局算法效果不佳 | 算法独立成纯函数，M1 验收前用 20 节点样例目测；必要时升级为成熟布局策略（04 §6.4） |
| React Flow 与树模式渲染冲突 | 两种模式共用一套节点组件；模式切换仅切换布局来源（04 §6.4） |
| JGit 读复杂仓库（子模块/大仓） | MVP 限定常规仓库；异常时提示改用 Git 命令行模式（04 §2 已留后路） |
| 中文 FULLTEXT 匹配不准 | ngram 解析器 + 验收用例覆盖中文短词；不满足则切换 LIKE 方案 |
